# S0 milestone record: environment and measurement

Written 2026-11-25. Covers issues #2 (doctor, locked environment) and #3 (measured training step).

Machine: Apple M5 (Mac17,2), 10 cores, 16 GiB, macOS 27.0.1, Python 3.12, torch 2.15.0.
Environment id `sha256:e160b01f246cda559f78e4495b259c8415f8c41e365d4ec8491fac0e87f9bef3`.

## What runs

- `uv run core-ultra doctor` reports the machine and the locked environment and saves a record.
- `uv run core-ultra measure step` times a complete training step (zero gradients, forward, loss, backward, optimiser update) of a placeholder scene model and reads its peak memory, for every size, batch size and device in `configs/measure/training-step-v1.json`. It saves a doctor record and a measurement record that names it by SHA-256. It refuses to start while another measurement is running.

**Apple GPU path.** No unsupported operation and no CPU fallback. All 15 Apple GPU cases ran with PyTorch's fallback switch off, where an unsupported operation stops the step, and one further run per size with PyTorch's MPS profiler on logged no CPU fallback. This covers the placeholder step's operations only; the training renderer's operations are checked in S3.

**Starting size.** d384-l6 (d_model 384, 6 layers, 8 heads, feedforward 1536; 10.73M parameters on the placeholder), the eligible size nearest the middle of the planned range. Recorded as `configs/scene-model/v1.json`, which names the measurement record by SHA-256.

**Neither memory nor time is the limit on this Mac for the measured step.** At batch 64 the chosen size peaks at 1.49 GiB against a budget of 8 GiB (half of memory), and one epoch of 20,000 examples takes 35 s against a budget of 300 s. No cloud run or lease is proposed, and none was started.

## What was tested

`uv run pytest`: the doctor and `measure step` commands are run for real on this machine on a configuration that finishes in seconds, and the tests assert on the records they produce (every case tied to a saved doctor record, 32-bit floats, planned positions, peak memory read, machine state recorded, fallback switch off, projections labelled and derived from the measured step, nothing identifying in the record, records never overwritten, a second measurement refused). The selection rule is tested on hand-written measurements for the cases that cannot be produced on demand (over the memory budget, over the time budget, CPU fallback, nothing eligible). Four tests check the committed evidence above: three sizes inside the planned range on both devices, AC power, the doctor record's hash, and that `configs/scene-model/v1.json` is the size the measurement chose.

Checked by hand, not by a test: the three ways an unsupported operation is detected were run against a real one. `torch.linalg.eig` on the Apple GPU raised `NotImplementedError` naming `aten::linalg_eig` with the fallback switch off, and with it on, both PyTorch's warning and its MPS profiler named the same operation. The patterns in `step_measurement.py` and `step_case.py` matched all three.

## What failed, and what limits the numbers

- **First attempt, 2026-11-24, discarded.** Issue 3 was started in two sessions at once. Their measurements overlapped on the GPU, on battery in Low Power Mode. No record was kept from either. `measure step` now refuses to start while another measurement is running, and records the power state of every case.
- **The machine was not idle.** Other applications were open. Swap in use was 3.5 to 4.7 GiB throughout and free memory before a case fell as low as 2.20 GiB. Three cases show it in their spread: d384-l6 batch 256 on CPU (median 1406 ms, maximum 2143 ms), d448-l7 batch 256 on CPU (median 1863 ms, maximum 2502 ms) and d256-l8 batch 64 on the Apple GPU (median 87 ms, maximum 114 ms). The chosen size at batch 64 on the Apple GPU ranged from 112.7 to 115.2 ms.
- **The CPU comparison is at PyTorch's default of 4 threads** on a 10-core machine. It was not tuned.
- **The placeholder is not the scene model.** Inputs and targets are random numbers, the input vocabulary is a guess, and the loss compares structural slots by position. The step costs what a model of this shape costs; it says nothing about what a model learns.
- **Peak footprint is of the whole process**, including the Python interpreter and PyTorch (about 0.4 GiB before the first step).
